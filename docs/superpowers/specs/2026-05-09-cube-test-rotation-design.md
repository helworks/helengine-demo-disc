# Cube Test Rotation Design

## Goal

Make the committed `city` cube-test scene rotate slowly at runtime so it can validate ongoing transform updates on every platform, including PS2.

## Scope

This change only affects the cube-test scene path that is currently the active startup/export target. It does not change the camera, light, renderer, or broader rendering-scene infrastructure.

## Approach

Add one small reusable runtime component in `city.rendering` that rotates its parent around the local Y axis using absolute elapsed time. Attach that component to the cube entity generated by `CubeTestSceneFactory`.

This keeps the scene authored through the same scene-generation path as the rest of `city`, while ensuring the runtime exercises:

- script component loading
- per-frame update execution
- quaternion orientation writes
- parent transform propagation into the renderer

## Component Design

Add a new component named `CubeTestSpinComponent`.

Responsibilities:

- expose `BaseYawRadians`
- expose `AngularSpeedRadians`
- during `Update()`, compute the current yaw from `Core.Instance.TotalElapsedSeconds`
- write `Parent.LocalOrientation` from that yaw

Implementation behavior:

- use deterministic absolute time instead of accumulating delta time
- rotate only on local Y
- keep the component self-contained and scene-agnostic apart from its name

Chosen defaults for the cube scene:

- `BaseYawRadians = 0f`
- `AngularSpeedRadians = PI / 2`

That yields one full turn every four seconds, which is slow enough to inspect visually while still making motion obvious on PS2.

## Scene Authoring Changes

Update `CubeTestSceneFactory` to attach the new script component record to `CubeTestCube`.

The cube remains:

- centered at the origin
- scaled to `2,2,2`
- using the existing cube model and standard material references

The camera and directional light remain unchanged so the only new moving part is the cube.

## Serialization

Add one helper in the rendering scene record factory layer, following the existing rendering script-component record pattern already used by the directional-shadow scenes.

The serialized record must include:

- stable script type id
- `BaseYawRadians`
- `AngularSpeedRadians`

This keeps the cube-test scene generated and committed like the other authored rendering scenes.

## Testing

Add focused source-level coverage that proves:

1. the cube-test scene factory emits the new spin component on the cube entity
2. the serialized record carries the expected slow-rotation defaults

After implementation, rebuild the PS2 cube ISO and verify the cube rotates visibly.

## Out of Scope

- changing renderer behavior
- adding editor controls for rotation speed
- generalizing this into a shared animation framework
- restoring the other rendering showcase scenes
